# 실패 사례로 바꾼 설계

| 관찰                                                                                                         | 바꾼 결정                                                                                                                                                                                                                              |
| ------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 서버가 “첫 검진”을 최근 검진으로 해석해 공복혈당 105 대신 95 mg/dL를 골랐습니다.                             | 서버는 검진표를 연결하고 모델은 전체 기록에서 검사일을 고르도록 역할을 나눴습니다. [시점 해석 실험](RECORD-SELECTION.md)                                                                                                               |
| 첫 출력 검사에 유리한 모델과 환자의 측정값을 더 직접적으로 설명하는 모델이 달랐습니다.                       | 처음 선택한 Llama를 유지할지 실제 화면 답변으로 다시 비교했습니다. [초기 선택](results/final/human-review.md) · [Qwen 선택 근거](RESULTS.md)                                                                                           |
| 짧은 예문을 사용하자 검사 항목과 측정값까지 빠졌습니다.                                                      | [짧은 예문 실험](results/ablation-short-example/stop-note.json)을 중단하고, 실제 JSON 형식으로 정상 답변과 판단 보류를 모두 보여줬습니다.                                                                                              |
| 문자열 검사는 같은 음수 값도 조사가 붙으면 거절했고, 재생성한 답변은 처음과 같은 항목을 누락하기도 했습니다. | 서버는 형식과 출처를 검사합니다. 설명은 한 번 생성하고, 의미 오류는 평가에서 원문과 검진표를 대조합니다. [재채점 기록](results/final/reading-regrade.json) · [재생성 비교](RETRY-REDUCTION.md) · [출력 필드 비교](OUTPUT-REDUCTION.md) |

현재 설계에서 가장 큰 한계는 실제로 존재하는 출처를 인용하면서 잘못된 판정을 내릴 수 있다는 점입니다. [최종 평가](RESULTS.md)에 개선 사례와 함께 남겼습니다.
