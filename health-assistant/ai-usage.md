# AI 활용: 구현 계획과 사용한 프롬프트

Codex로 NestJS·LangGraph 연결, 테스트, 모델 비교 도구와 문서 초안을 작성했습니다. 기술 스택과 테스트 방향은 직접 정하고 두 모델의 화면 답변을 블라인드로 비교해 기본 모델을 선택했습니다. Codex가 답변을 검진표와 대조한 기록은 사용자 평가와 구분했습니다.

## 구현 계획

1. 과제 JSON의 키와 문자열 측정값을 보존하는 Mock API를 만들고 HTTP로 조회합니다.
2. 측정값에 단위와 참고표를 연결합니다. 모델은 전체 기록에서 검사일과 항목을 선택해 한 번에 설명합니다.
3. 고정된 출력으로 입력·JSON·인용 출처·장애 처리를 테스트한 뒤, 같은 질문으로 실제 두 모델을 비교합니다.
4. 기본 모델을 정한 뒤 예시만 바꿔 다시 실행합니다. 출처 일치 건수와 설명의 오류를 별도로 검토합니다. [검토 결과](evaluation/RESULTS.md)

## 개발에 사용한 주요 요청

다음은 기술 스택, 테스트 방식, 마지막 프롬프트 실험을 결정한 요청의 원문입니다.

> 그럼 NestJS로 진행하자. 우선 니가 설계해준 것들 잘 읽어봤고, 그대로 진행하면 돼.
> Ollama 응답 비교는 어떤 식으로 할 거야?
> 그리고 테스트는 그 차이가 별로 크지 않다면 Classicist로 통일하고 싶음.

> 모든 구현에는 이유가 있어야 하고, 그걸 문서화할 수 있어야 해. 내가 면접에서 어떤 질문을 받아도 설명할 수 있도록.
> 로깅이나 증거를 남길 수 있다면 최대한 남겨서 내가 설명할 근거를 만들 수 있도록 해줘.

> 운영 그래프와 JSON·출처 검증은 유지하고, 프롬프트 예시 보완과 자연어 문자열 채점 제거만 적용해. 기존 질문으로 before-after 비교해서 결과도 남겨줘. 커밋과 푸시는 하지 마.

## 최종 운영 프롬프트

모델에는 시스템 지시와 함께 정상 사례 두 개, 보류 사례 한 개, 해당 환자의 전체 검진 기록, 실제 질문을 전달합니다. 아래는 [모델 코드](src/assistant/model.ts)에서 생성한 합성 환자 `demo-001`의 입력입니다.

```text
질문에서 지정한 시점의 기록을 사용하고, 시점 언급이 없으면 최근 기록으로 답하세요. sources에는 실제 사용한 검사일/검사명만 넣고 해당 기록이 없으면 빈 배열을 반환하세요.
전체 요약은 BMI·공복혈당·혈압, 콜레스테롤 전반은 기록에 있는 총콜레스테롤·HDL·LDL을 설명하세요.
한국어 한두 문장으로 질문한 항목의 검사일·측정값·단위와 해당 행의 검진표 판정을 그대로 전하세요. 분류 보류면 측정값과 보류 이유만 답하세요.
생활 안내는 필요할 때만 짧게 덧붙이고 질환 확정이나 복약 변경은 피하세요.
```
