# ADR-002 · 답변을 한 번 생성하고 인용한 기록을 확인합니다

서버가 모델의 잘못된 답변을 사전에 걸러내려면 무엇을 오류로 판정할지 기준을 명확히 정해야 합니다. 초기 구현에서는 모델의 설명 문장에서 특정 문자열 표기를 규칙 기반으로 검색했습니다. 그러나 정답과 동일한 음수 수치를 제시한 답변도 ‘T-score는 -0.8’처럼 한국어 조사가 붙었다는 이유만으로 서버가 올바른 답을 거절하는 문제가 발생했습니다. [당시 답변 재검토](../../evaluation/results/final/reading-regrade.json)

## 고려한 선택지

| 선택지 | 얻는 점 | 감수하는 점 |
| --- | --- | --- |
| 설명 내용까지 문자열로 검사하고, 검증 실패 시 다시 생성합니다. | 초기 Qwen 실험에서 두 검진을 비교한 답변은 교정 지시를 거친 뒤 두 번 모두 당시 검사를 통과했습니다. | 한국어 표현만 다른 정답을 거절할 수 있고, 추가 호출 후에도 모델이 같은 항목을 반복해서 누락할 수 있습니다. |
| 한 번 생성한 답변의 JSON 형식과 인용 출처만 검사합니다. | 한국어 표현이 다양하더라도 인용한 검사일과 항목이 환자의 실제 기록에 존재하는지 서버가 객관적으로 확인할 수 있습니다. | 인용한 출처가 실재하더라도 설명문에 잘못된 의학적 판정이 포함될 수 있습니다. 또한 첫 응답이 형식 검사에 실패하면 추가 교정 기회 없이 안내 문구로 종료됩니다. |

## 결정과 근거

검진 기록이 있는 정상 요청에 대해 서버는 Ollama를 한 번만 호출합니다. 서버는 모델이 반환한 JSON의 `sources`(출처)와 `explanation`(설명) 필드를 검사합니다. 설명에 공백 이외의 문자가 있고 출처 배열이 비어 있지 않으며 인용된 모든 항목이 해당 환자의 실제 기록에 포함되어 있다면, 서버는 설명을 사용자 화면에 그대로 표시합니다. 반면 JSON 형식이 잘못됐거나 설명이나 출처가 비었거나 출처가 기록과 일치하지 않으면, 서버는 “해당 검진을 특정할 수 없습니다.”라는 정형화된 안내 문구를 반환합니다. ## 재시도를 줄이면 얼마나 빨라집니까?

초기 파이프라인 그래프는 `lookup → select → generate → validate → complete`의 5개 노드로 처리했습니다. 이때 검증에 실패하면 `validate`에서 `generate`로 **최대 한 번** 돌아가 재시도를 수행했습니다. 기존 5개 노드를 유지한 Llama 실험에서는 근거 항목이 빠진 답변에 한해 재시도를 생략해 보았습니다. 그 결과 영향을 받은 4건의 평균 응답 시간은 **8.65초에서 5.96초**로 줄었고, 서버의 대체 응답 로직 덕분에 사용자 화면에 표시된 최종 결과는 동일했습니다. 다만 모델을 사용한 전체 24건의 p95 응답 시간은 9.00초에서 9.82초로 늘어났습니다. [재시도 전후 비교](../../evaluation/RETRY-REDUCTION.md) · [교정이 도움이 된 사례](../../evaluation/results/final/case-results.md)

현재 파이프라인 그래프는 검진 기록이 있으면 `lookup → generate → complete`의 3개 노드를 거칩니다. 질문에 맞는 검사일과 항목은 모델이 프롬프트를 보고 직접 고르며, 서버는 `generate` 노드 안에서 JSON 형식과 출처 실재 여부를 확인합니다. 따라서 그래프 차원의 재시도는 0회입니다. 최종 Qwen 평가에서 “두 검진의 공복혈당을 비교해 주세요”라는 질문은 전체 응답까지 7.88초가 걸렸고, 이 중 한 번의 LLM 생성 단계에 7.86초를 사용했습니다. 같은 평가에서 모델을 호출한 19건 전체의 응답 시간은 중앙값 5.95초, p95 15.84초였습니다. ## 남은 한계

최종 Qwen 평가에서 혈압 118/92에 관한 답변은 올바른 검진 기록을 출처로 인용하고도 설명에서는 정상(A)이라고 잘못 판정했습니다. 이처럼 현재 시스템에서 상태가 `generated`로 판정된 것은 JSON 형식과 출처 검사를 통과했음을 의미할 뿐이며, 설명문 속 판정 내용까지 검증되었음을 보장하지는 않습니다. 따라서 향후 판정 오류를 줄이는 개선 작업은 출처 일치율과 별개로, 설명문 속 판정이 서버의 참고표 분류 결과와 일치하는지 교차 대조하는 검증 체계를 갖추어야 합니다.
