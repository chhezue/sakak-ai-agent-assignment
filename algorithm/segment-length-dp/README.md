# 구간 분할과 길이 DP

[구현](solution.ts)은 조각별로 변환 후의 길이를 구하고, 가운데 두 위치가 속한 조각만 따라갑니다. 길이를 더하려면 먼저 두 조각을 따로 변환한 결과가 통째로 변환한 결과와 같다는 보장이 필요합니다.

## 한 번 분리된 경계도 다시 합쳐질 수 있습니다

| 변환 | 통째로 읽기 | 경계를 고정하고 읽기 |
| ---- | ----------- | -------------------- |
| 시작 | `211`       | `2 ｜ 11`            |
| 1회  | `1221`      | `12 ｜ 21`           |
| 2회  | `112211`    | `1112 ｜ 1211`       |

첫 변환까지는 양쪽 조각을 붙인 값이 정답과 같습니다. 하지만 다음 변환에서는 경계의 두 `2`를 하나의 묶음으로 읽어야 합니다. 현재 경계의 숫자가 다르다는 사실만으로는 분할할 수 없습니다.

왼쪽 조각을 변환하면 마지막에 쓰는 숫자는 항상 그 조각의 마지막 숫자입니다. 따라서 **남은 각 변환 직전에 오른쪽 조각의 첫 숫자가 이 값과 다르면** 두 조각을 따로 읽을 수 있습니다. 오른쪽은 최대 64자의 접두부만 추적합니다. 예를 들어 `11122…`에서 끝의 `22`는 더 이어질 수 있으므로 완결된 `111`만 다음 접두부에 반영합니다. 다음 첫 숫자를 확인할 수 없으면 그 경계에서는 나누지 않습니다. 어느 경계도 증명할 수 없을 때는 조각 전체를 한 번 변환합니다.

## 길이로 원하는 위치만 읽습니다

`(조각, 남은 변환 횟수)`를 키로 확장 길이를 저장합니다. 안전하게 나눈 조각은 자식 길이를 더하고, 한 번 변환한 조각은 그 결과의 길이를 사용합니다. 목표 인덱스가 왼쪽 길이보다 크거나 같으면 왼쪽 길이를 빼고 오른쪽으로 이동합니다.

예를 들어 `122`를 두 번 변환하면 `1 → 11 → 21`과 `22 → 22 → 22`라는 두 독립 조각을 얻습니다. 가운데 인덱스 1은 왼쪽의 두 번째 문자 `1`이고, 인덱스 2는 왼쪽 길이 2를 뺀 오른쪽의 첫 문자 `2`입니다. 답은 `12`입니다.

## 시간·공간 복잡도

서로 다른 길이 상태 수를 S, 최대 조각 길이를 B, 접두부 예산을 P, 캐시한 경계 검사 수를 C라고 합니다. 한 상태의 후보는 최대 B개입니다. 후보마다 문자열을 자르고 최대 n단계의 접두부를 확인하므로 시간 상한은 O(S × (B² + B × n × P))입니다. 상태와 경계 캐시에 필요한 문자열 공간은 O(SB + CP)입니다. 길이와 인덱스는 `bigint`로 계산하며, 길이 M을 저장하는 정수에는 별도로 O(log M)비트가 필요합니다.

조각이 작게 유지된 결과는 시작값 `1`과 범위 4~99에서 확인했습니다. 임의의 시작값에서도 상태 수가 작다는 보장은 없습니다. `algorithm` 디렉터리에서 `npm ci` 후 `npm run test:segment-length-dp`로 [경계 반례와 상한 테스트](solution.test.ts)를 실행합니다. [측정 결과](../README.md#35항은-전체-생성이-빨랐고-99항은-구간-분할로-풀었습니다)
